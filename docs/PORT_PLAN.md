# NatroMacroAndroid — план порта 1:1 (по сканированию исходников)

> Цель: полный функциональный паритет с **Natro Macro** (desktop, AHK v2) на Android,
> с гарантией работы при **20 FPS** на телефоне, без инжекта в Roblox.
> План построен по реальному сканированию репозиториев:
> `NatroTeam/NatroMacro` (439 файлов, ядро `submacros/natro_macro.ahk` — 23 029 строк)
> и `nosyliam/revolution-macro` (архитектура-референс: модели + датасеты).

---

## 1. Что именно портируем: инвентарь Натро (результат скана)

Главный цикл Натро: `Loop for i in priorityList → nm_<Task>()` — пользовательский
приоритетный список задач. Задачи, найденные в исходнике:

### 1.1 Сбор (Gather)
- `nm_GoGather` / `nm_gather` — до 3 полей за цикл, настройка на каждое поле:
  паттерн, размер, повторы, поворот/инверсия, `Until Pack %`, способ возврата
  (Reset / Walk), позиция старта, спринклер.
- Движок `Walk(n)` (lib/Walk.ahk): **1 тайл = 4 стада**, длительность считается
  интегрированием живой скорости: `DetectMovespeed()` каждый шаг читает бафф-бар
  (стеки haste через OCR цифр-битмапов, haste+, oil, smoothie, bear-баффы,
  coconut haste) и применяет формулу скорости. `hasteCap` — порог компенсации.
- 12 паттернов (папка `patterns/`): Snake, Lines, Squares, Diamonds, Slimline,
  SuperCat, XSNAKE, CornerXSnake, Fork, e_lol, Auryn, Stationary.
- `nm_fieldDriftCompensation` — слежение за сатуратором (дрейф поля).
- `nm_setSprinkler` / `nm_JumpSprinkler` / `nm_LocateSprinkler` — типы спринклеров,
  прыжковая постановка, поиск своего спринклера по картинке.
- `nm_loot` — подбор лута после фарма/мобов.

### 1.2 Коллекция (Collect) — каждая задача = путь `gtc-*` + логика
- Wealth Clock, Blender (+ротация 3 предметов, inf/кол-во), Ant Challenge (+авто-покупка прохода),
  Robo Pass (+RBP Delevel), Honey/Treat/Blueberry/Strawberry/Coconut/Glue/RoyalJelly диспенсеры,
  Sticker Printer (+детект яйца),
  Beesmas: Wreath, Stockings, Feast, Gingerbread House, Snow Machine, Candles,
  Samovar, Lid Art, Gummy Beacon, Honeystorm, HoneyLB,
  Memory Match (normal/mega/extreme/winter) — с полноценным **решателем** `nm_SolveMemoryMatch`.

### 1.3 Бусты (Boost)
- Полевые бустеры (`nm_toBooster`/`nm_toAnyBooster`, пути `gtb-*`), приоритет сбора в забустенном поле.
- Sticker Stack (предмет/режим/скины/таймер),
- Wind Shrine (+ротация),
- AutoFieldBoost: дичайшая логика с dice, glitter, лимитами, часами деактивации.
- `nm_boostBypassCheck`.

### 1.4 Убийства (Kill)
- `nm_Bugrun` — маршрут по мобам (ladybug, rhino, werewolf, spider, scorpion,
  mantis, beetle...) с таймерами респауна `nm_MonsterRespawnTime`, пути `wf-*`.
- Mondo Chick (`nm_Mondo`: kill/loot/tag по расписанию).
- Vicious Bee: `nm_VBCheck` (ночной детект) → `nm_locateVB` → `nm_killVB` + сохранение стингеров.
- Боссы: Stump Snail (детект HP-бара `nm_HealthBar`, лимит времени),
  Coconut Crab, King Beetle, Chick (`nm_setChickHealth`, `nm_KillTimeEstimation`).

### 1.5 Квесты (Quests)
- Honey Bee, Polar, Riley, Bucko, Black Bear, Brown Bear — по каждой паре:
  `nm_XQuest` + `nm_XQuestProg` (чтение прогресса из интерфейса квеста),
  `nm_QuestRotate`, настройка `QuestGatherReturnBy`.

### 1.6 Плантеры (Planters)
- Полный цикл: размещение (`nm_gotoPlanter`, до 3 шт), рост с таймингами
  (`nm_PlanterTimeUpdate`, `nm_PlanterDetection` по скриншотам `nm_planterSS`),
  сбор по интервалу или «полный», нектарные пресеты/приоритеты/мин-%,
  ручные плантеры, `HarvestFullGrown`, `GotoPlanterField`, `GatherFieldSipping`,
  `MaxAllowedPlanters`, MPuff-режим.

### 1.7 Ресет / улей / респаун
- `nm_Reset` → `nm_HealthDetection` → `nm_ConfirmAtHive` / `nm_DetectSpawn`,
- `nm_detectHiveSlots` / `nm_findHiveSlot` / `nm_claimHiveSlot` (1–6 слоты, детект «свободен/занят»),
- `nm_SetHiveCameraDirection`, `nm_setShiftLock`, `nm_AmuletPrompt`.

### 1.8 Ре-коннект
- Детект дисконнекта/краша (окно загрузки `loading.png`, «наука»-экран `science.png`),
  перезапуск Roblox по **серверной ссылке** (приватка), `ReconnectMethod`,
  `ClaimMethod` (claim hive при входе), расписание ре-джойнов
  (интервал/час/минута), **публичный фоллбек**, если приватка не пускает.

### 1.9 Инфраструктура
- Приоритетный список задач (порядок выполнения),
- `nm_hotbar` + `nm_HotbarWhile` (использование слотов хотбара по расписанию/условиям),
- статистика (`nm_setStats`, `IncrementStat`), вебхуки, `Heartbeat`, ночные
  объявления, `nm_Night` (детект ночи), `HyperSleep` (точные паузы),
  глобальный `KeyDelay`, горячие клавиши, авто-старт, дебаг-лог.

### 1.10 Референс: как это делает Revolution
- Экран → **нейросети** (ONNX): `token_detection`, `vic_detection`, `sprinkler`,
  OCR (`text_detection`+`text_recognition`), вместо пиксель-темплейтов.
- Паттерны/пути — бинарные датасеты (`datasets/*/patterns.bin`), версии v2–v8.
- Вывод для нас: чистые темплейты хрупки на мобильном рендере — нужен слой
  детекторов, а не тупой перенос `Gdip_ImageSearch`.

## 2. Ключевые соответствия механизмов Натро → Android

| Натро (десктоп) | Порт на Android | Комментарий |
|---|---|---|
| Клавиши WASD | Джойстик: `dispatchGesture` drag + `continueStroke` | Уже есть в 0.3.2 |
| Мышь (камера) | Свайп по правой половине экрана | Отдельная зона камеры, калибруемая |
| Прыжок/клавиши | Калибруемые кнопки-тапы | Уже есть |
| Захват окна + `Gdip_ImageSearch` | `takeScreenshot()` accessibility + **детекторный слой** (см. §4.3) | Главное отличие от 0.3.2 |
| `Walk(n)` + `DetectMovespeed` | Тот же интегратор времени + чтение бафф-бара со скриншота | Работает при любом FPS |
| Меню/кнопки по картинке | Поиск узлов Accessibility по тексту (рус/англ) + тап-фоллбек | Уже есть для ресета |
| Рестарт по диплинку `roblox-player://` | Intent c deep link `robloxmobile://placeID=...&gameInstanceId=...` (placeId+gameInstanceId парсятся из приват-ссылки) | Проверить схему на актуальном клиенте в Фазе 8 |
| `HyperSleep` | `SystemClock.sleep` с дедлайнами и прерыванием по STOP | Уже есть `sleepRunning` |
| INI-конфиг | JSON-конфиг + импорт натровского `settings/*.ini` где возможно | Совместимость конфигов — часть «1 в 1» |

## 3. Требования «20 FPS»: обязательные правила архитектуры

Телефон держит ~20 кадров/с → кадр каждые 50 мс, анимации медленные, промпты
появляются с задержкой. Правила, нарушение которых запрещено:

1. **Никаких таймингов, привязанных к кадрам.** Всё движение — интегрирование
   времени × скорость (как `Walk()`). Длительность жеста считается от
   `студах/скорости`, а не от «сколько кадров подержать».
2. **Любое ожидание события = цикл «скриншот → проверка → ретрай» с окном таймаута**,
   а не `sleep(ровно_столько_сколько_надо)`. Каждый детект: `minWait`, `maxWait`,
   шаг ресканирования ≥ 150 мс (чтобы не душить рендер на 20 FPS).
3. **Детекты терпимы к пропуску кадров:** порог «уверенности» по нескольким
   кадрам подряд (например, улей = золото в 2 из 3 сканов), а не по одному кадру.
4. **Мультимасштабный/толерантный матчинг картинок**: мобильный рендер ≠ десктоп
   (освещение, AA, разрешение, ориентация). Темплейты собираются **с мобильного
   клиента** в режиме калибровки, матчинг с допуском по цвету и масштабу.
5. **Очередь скриншотов с троттлингом**: не чаще ~4–5/с, переиспользование
   последнего кадра; `Bitmap.recycle()` обязателен (иначе OOM на длинных сессиях).
6. **Тайминги «прыжок из пушки» и похожие — с окном допуска**: не тап в момент X,
   а серия тапов в окне [X−δ, X+δ] + проверка результата (долетел/не долетел →
   повтор маршрута).
7. **Ватчдог**: любая задача, висящая дольше своего бюджета, передаёт управление
   менеджеру состояний (рестарт задачи → ресет → реконнект), ничего не должно
   «вечно спать».
8. **Скриншоты не блокируют ввод**: детект работает параллельно с удержанием
   джойстика (как сейчас `continueStroke`), кроме моментов, где нужна полная остановка.

## 4. Целевая архитектура приложения

### 4.1 Слои
```
ui/            MainActivity (вкладки как у Натро: Gather/Collect/Boost/Quests/
               Planters/Status/Settings), CalibrationOverlay, ControlOverlay
core/          MacroOrchestrator — приоритетный цикл задач (аналог priorityList),
               StateMachine, Watchdog, TaskBudget
input/         GestureDriver (джойстик/тапы/свайпы/удержания, очередь, отмена),
               InputCalibration
vision/        FrameSource (takeScreenshot, троттлинг),
               Detectors: HiveSlotDetector, SpawnDetector, BackpackDetector,
               BuffBarReader (haste-стеки), ProximityPromptDetector («E»),
               CannonDetector, SprinklerDetector, MatchBoardDetector,
               HealthBarDetector, NightDetector, DisconnectDetector,
               TemplateStore (захват темплейтов с экрана + версии)
tasks/         gather/ collect/ boost/ kill/ quests/ planters/ reconnect/
paths/         Порты всех путей из папок paths/ как JSON-маршруты
               (точки: джойстик-вектор+тайлы / тап / камера / ожидание / детект)
walk/          WalkEngine (интегратор), PatternLibrary (12 паттернов),
               MoveSpeedEstimator (по бафф-бару)
config/        JsonConfig, NatroIniImporter, FieldDefaults
infra/         Logger (сессии), Stats, WebhookSender, Heartbeat, PrefsLock
```

### 4.2 Менеджер состояний (главное отличие от текущего кода)
Текущая 0.3.2 — линейный скрипт маршрута. Для 1:1 нужен явный цикл:
```
IDLE → (START) → RESET_CHECK → HIVE → ROUTE_TO(field/task) → TASK
  → CONVERT_CHECK(рюкзак%) → обратно в приоритетный цикл
  в любой точке: LOST_ROBLOX → RECONNECT → CLAIM → HIVE
                 WATCHDOG_TRIP → RETRY(3) → RESET → RECONNECT
```

### 4.3 Vision-стратегия (двухслойная, как гибрид Натро+Революшн)
1. **Слой 1 — быстрые цветовые/структурные детекторы** (как сейчас в 0.3.2,
   но обобщённые): улей/спавн, пушки, спринклер, рюкзак-иконка, ночь.
   Дёшево, без зависимостей, 2–3 мс на кадр.
2. **Слой 2 — темплейт-матчинг с допуском** по темплейтам, снятым **с мобильного
   клиента** (режим «захвати и подпиши» в приложении: выдели область → назови →
   сохрани в TemplateStore с метаданными версии игры).
3. Опционально позже (не блокирует паритет): лёгкая ONNX-модель детекта токенов
   (референс — `models/*/token_detection.bin` у Revolution) для «умного» сбора.
   Это уже апгрейд **сверх** Натро, откладываем после паритета.

### 4.4 Данные путей и паттернов
- Все 12 паттернов генерируются кодом (формулы перенесены из `patterns/*.ahk`).
- Пути (`gtf-*`, `gtc-*`, `gtp-*`, `gtq-*`, `gtb-*`, `wf-*` — ~120 штук) —
  **JSON**: последовательность шагов `{type: move|tap|camera|wait|detect|prompt,
  params}`. Десктопные «клавиша+тайлы» переводятся в «вектор джойстика+тайлы»
  с сохранением геометрии; каждая точка верифицируется на телефоне и получает
  пометку «проверено на устройстве/разрешении».
- Версионирование датасета путей (как у Revolution `v2..v8`): при обновлении
  игры правим датасет, а не код.

## 5. Фазы работ и критерии готовности

### Фаза 0 — Фундамент (перезакладка 0.3.2)
- Вынести текущий Pine Tree маршрут в новую архитектуру (§4.1–4.2) без изменения поведения.
- Ватчдог, бюджеты задач, логирование сессий, корректная отмена жестов.
- Калибровка: джойстик, зона камеры, кнопки (прыжок), разрешение экрана.
- **Выход:** текущий маршрут работает не хуже, чем в 0.3.2, на 20 FPS,
  падает в ретрай, а не в «мёртвый стоп».

### Фаза 1 — Движение уровня Натро
- `WalkEngine`: интеграция времени × живая скорость; `MoveSpeedEstimator` по
  бафф-бару мобильного клиента (haste-стеки, haste+, oil, smoothie, bear) —
  перенос формулы из `Walk.ahk` 1:1, включая `hasteCap`.
- Все 12 паттернов; размер/повторы/инверсия/поворот как в настройках Натро.
- Камера: повороты на N шагов, pitch, шифт-лок-эквивалент (фикс камеры).
- **Выход:** на пустом поле персонаж проходит Snake 11×size за то же число
  тайлов (±1 тайл за 10 мин), что и Натро на ПК, при 20 FPS.

### Фаза 2 — Ресет/улей/спавн + все 17 полей
- Полная цепочка `nm_Reset`: здоровье-детект, подтверждение улья, детект спавна,
  до 3 попыток — уже частично есть, довести до детерминизма на 20 FPS.
- Детект и захват слота улья (1–6, свободен/занят) — аналог `nm_claimHiveSlot`.
- Маршруты **ко всем 17 полям** (`gtf-*`): dandelion, sunflower, mushroom,
  blue flower, clover, spider, strawberry, bamboo, pineapple, cactus, pumpkin,
  coconut, rose, pine tree, stump, mountain top, pepper.
- **Выход:** из улья макрос доходит до центра любого выбранного поля ≥ 19/20 попыток.

### Фаза 3 — Сбор и конвертация (ядро фарма)
- Детект **полного рюкзака** (иконка/полоса) + настройка `Until Pack %`.
- Конвертация у улья (`nm_convert`): возврат к улью, ожидание конвертации,
  подтверждение по изменению счётчика мёда.
- Спринклеры: постановка (обычная/прыжковая), поиск своего, типы.
- Возврат на поле методами Reset / Walk (как `FieldReturnType`).
- Drift compensation (сатуратор) — упрощённая версия по смещению камеры.
- **Выход:** 8-часовой цикл «поле→конверт» без участия человека; мёд/час
  в пределах ожиданий для данного хайва.

### Фаза 4 — Коллекция
Диспенсеры и автоматы по списку §1.2, каждый со своим `gtc`-путём и детектом
куллдауна (визуальный таймер/серый промпт):
- **Выход:** полный проход «коллекции» за один цикл, ничего не пропущено,
  кулдауны отслеживаются, Beesmas-часть включается флагом как у Натро.
- Решатель Memory Match (`nm_SolveMemoryMatch`) — порт алгоритма, поле читается
  по скриншоту доски.

### Фаза 5 — Бусты
- Полевые бустеры (`gtb-*`), Sticker Stack, Wind Shrine, Boost Chaser,
  AutoFieldBoost (dice/glitter/лимиты), сбор в забустенном поле.
- **Выход:** буст активен ≥ 95% времени своего окна, приоритеты работают.

### Фаза 6 — Убийства
- Bugrun по всем мобам с таймерами респауна, `wf-*` пути.
- Mondo по расписанию (детект времени в игре), Vicious Bee ночью
  (детект ночи → поиск → килл), боссы: Snail (детект HP-бара, тайм-лимит),
  Coconut Crab, King Beetle, Chick.
- **Выход:** все респаун-таймеры Натро дают те же окна; киллы ≥ 19/20 попыток.

### Фаза 7 — Квесты
- Все 6 квест-гиверов + чтение прогресса из окна квеста (аналог `*_QuestProg`),
  `QuestRotate`, квест-ориентированный сбор.
- **Выход:** квесты завершаются автоматически, прогресс читается корректно.

### Фаза 8 — Плантеры и реконнект
- Плантеры: полный цикл размещения/роста/сбора (§1.6), нектарные пресеты.
- Реконнект: детект вылета/краша, перезапуск по приват-ссылке через deep link,
  claim улья, расписание ре-джойнов, публичный фоллбек.
- **Выход:** 24-часовая сессия переживает ≥ 3 принудительных вылета без участия
  человека и возвращается к фарму.

### Фаза 9 — Инфраструктура паритета
- Хотбар (`nm_hotbar`, условия), приоритетный список задач как у Натро (порядок,
  вкл/выкл каждой задачи), статистика сессии/всего, вебхуки, ночные события,
  авто-старт после перезапуска приложения.
- Импорт натровских настроек (максимально возможный на мобильных реалиях).
- **Выход:** вкладка-в-вкладку паритет настроек с Натро (кроме специфично-десктопного).

### Фаза 10 — Стабилизация 20 FPS + приёмка
- Прогон всей матрицы тестов (§6) на 20 FPS и на 30/60 для сравнения.
- Бенчмарк мёд/час на эталонных сценариях (соло-фарм, коллекция, багрун).
- Недельный марафон 24/7 с ватчдогом; цель: 0 необработанных зависаний.

## 6. Матрица приёмки «без ошибок»

Для каждого модуля — автотест на телефоне:

| Модуль | Тест | Критерий |
|---|---|---|
| Ходьба | 10 мин по каждому паттерну | дрейф ≤ 1 тайл |
| Ресет | 20 подряд | 20/20 улей, 0 ложных «спавн» |
| Маршруты полей | 20 попыток на поле | ≥ 19/20 |
| Конверт | цикл до 100% рюкзака ×10 | 10/10 |
| Диспенсеры | полный проход ×3 | 0 пропущенных активных |
| Мобы | по 10 киллов | ≥ 9/10 на каждого |
| Память-матч | 10 игр | ≥ 8 завершённых |
| Реконнект | 5 краш-тестов | 5/5 возврат в фарм |
| 20 FPS | всё выше | деградация успеха ≤ 5% против 60 FPS |

Плюс: лог каждой сессии сохраняется в файл (как дебаг-лог Натро) — разбор
любого сбоя по пост-мортему без воспроизведения.

## 7. Риски и как они закрываются

| Риск | Мера |
|---|---|
| Мобильный рендер ломает темплейты | Темплейты снимаются с телефона + допуски + версии датасета |
| Роблокс поменяет мобильное меню | Узлы ищем по тексту (рус/англ) в первую очередь, координаты — только фоллбек |
| 20 FPS ломает тайминги пушек/прыжков | Окна допуска + проверка результата + повтор |
